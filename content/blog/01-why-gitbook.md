## 시작은 한 튜토리얼 사이트

42 서울 webserv 과제를 하다가 GitBook 으로 만든 튜토리얼 사이트를 봤다. 내용도 좋았지만 화면이 더 눈에 들어왔다.

- 왼쪽에는 전체 글 목록이 있고, 지금 읽는 글이 파랗게 표시된다.
- 가운데 본문은 폭이 적당해서 긴 글도 읽기 편하다.
- 오른쪽에는 "이 페이지에서" 목차가 따라다닌다.

기술 블로그도 이렇게 생기면 좋겠다고 생각했다. 글을 시간순으로 쌓는 블로그보다, 주제별로 찾아 읽는 문서에 가까운 모양이다.

## 세 가지 길

| 방법 | 좋은 점 | 걸리는 점 |
|---|---|---|
| GitBook 을 그대로 쓰기 | 바로 쓸 수 있다 | 디자인과 주소를 내 마음대로 바꾸기 어렵다 |
| Jekyll·Hugo 테마 고르기 | 테마가 많고 GitHub Pages 와 잘 맞는다 | 원하는 3단 화면에 딱 맞는 테마를 찾거나 고쳐야 한다 |
| 생성기부터 직접 만들기 | 화면과 기능을 전부 내가 정한다 | 처음부터 다 만들어야 한다 |

나는 세 번째를 골랐다. 지금 이 블로그의 코드는 생성기, 미리보기 서버, 템플릿, 스타일, 스크립트를 합쳐 2,150줄 정도다. 전부 읽을 수 있는 양이라서, 마음에 안 드는 곳이 생기면 바로 고칠 수 있다.

> [!NOTE]
> 이 블로그는 Claude Code 와 함께 만들었다. 나는 원하는 모습과 고칠 점을 말하고 화면을 확인했고, 코드는 대부분 Claude 가 썼다. 이 시리즈는 그 과정에서 정한 것과 막힌 것을 정리한 기록이다.

## 화면을 재다

GitBook 의 CSS 파일을 가져오지는 않았다. 대신 브라우저 개발자 도구에서 요소마다 실제로 적용된 값을 읽었다.

```js title="개발자 도구 콘솔"
const pick = (selector, props) => {
  const style = getComputedStyle(document.querySelector(selector));
  return Object.fromEntries(props.map((p) => [p, style.getPropertyValue(p)]));
};

pick("main h1", ["font-size", "line-height", "font-weight", "letter-spacing"]);
// { "font-size": "36px", "line-height": "45px", "font-weight": "700", "letter-spacing": "-0.9px" }
```

이렇게 읽은 값을 표로 모았다. 세 칸 화면의 뼈대는 이 숫자들로 정해진다.

| 자리 | 값 |
|---|---|
| 헤더 높이 | 64px |
| 왼쪽 목록 폭 | 288px |
| 본문 최대 폭 | 768px |
| 오른쪽 목차 폭 | 256px |
| 글 제목 | 36px / 행간 45px / 굵기 700 |
| 본문 | 16px / 행간 26px |
| 코드 | 14px / 행간 20px |

색도 같은 방식으로 읽어서 회색 12단계와 파랑 몇 단계로 정리했다. 이 표가 첫 번째 테마의 설계도가 됐다.

> [!TIP]
> 값을 재서 다시 만들면, 남의 코드를 복사하지 않으면서도 화면의 비율과 리듬은 그대로 가져올 수 있다. 다만 숫자를 그대로 옮긴다고 읽기 편해지는 것은 아니었다. 그 이야기는 3편에 있다.
